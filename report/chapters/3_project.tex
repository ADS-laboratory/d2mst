The implementation is organized as a fully distributed system with one process per network node. Every process runs the same code base, but its behavior depends on the role it currently plays in the spanning tree and on the state of the network.

\section{Protocols and Algorithms}

We assume that initially the network has already converged to a minimum directed spanning tree (or
a set of minimum spanning trees if the network is not connected). The system reacts to
topological changes by executing a failure response protocol when a tree link fails, and a
addition response protocol when a new link is added to the network. Here is an overview of how the protocols work:

\begin{itemize}
  \item \textbf{Failure response protocol:} when a tree link fails, the spanning tree is split into two fragments. The protocol identifies the minimum-weight edge that connects the two fragments and adds it to the MST, restoring connectivity. We provide two procedures to do so:
  \begin{itemize}
    \item a naive approach that tests all edges to check whether they are outgoing, with $O(e)$ message complexity;
    \item a more efficient approach that performs a binary search over the range of edge weights, with $O(n\log n)$ message complexity. The root first estimates a median weight $m$ for the current interval $[a,b]$ and uses it to split the search space into $[a,m]$ and $[m{+}1,b]$. It then checks whether an outgoing edge exists in either interval by exploiting the fact that outgoing edges have only one node in the fragment while all other have two. The root keeps the smaller sub-interval that still contains at least one outgoing edge and repeats the process until only one weight remains. That final weight is
    the minimum outgoing edge weight.
  \end{itemize}
  \item \textbf{Addition response protocol:} when a new link is added to the network, a cycle is created in the MST. The protocol identifies the maximum-weight edge in that cycle by propagating a message from both endpoints of the new link toward the root. The first node that receives both messages is the least common ancestor of the two endpoints and holds the maximum weight in the cycle. The least common ancestor then sends a message to properly update the topology inside the cycle, removing the maximum-weight edge and adding the new link to the MST.
\end{itemize}

In the next sections we describe the protocols in detail, including how multiple concurrent topological changes are handled.
\subsubsection{Ids}

These topological changes can fragment the MST into multiple disjoint fragments. To
correctly execute the \emph{response} protocols, each node maintains a unique
\emph{fragment identity} that is updated whenever the fragment is split or merged.

Intra-fragment messages carries the sender's current fragment identity. Upon receiving any
of these messages, a node first checks whether the received identity matches its own
current identity; if it does not, the message is \emph{silently discarded}.

This check is the mechanism by which the protocol handles concurrent topological changes.
When a new failure causes a fragment to adopt a fresh identity, all messages generated
under the previous identity become instantly invalid: they will be rejected by every node
they subsequently reach, without any explicit cancellation or coordination.

In order for this mechanism to work, topological changes create new fragments with new
identities that are guaranteed to be unique across the entire network.

\subsubsection{Failure response protocol}

In a network that has converged to a minimum spanning tree, when a tree link
$e = (u, v)$ fails (with $u$ the parent of $v$ in the current MST), the spanning tree
is split into two \emph{fragments} that must be reconnected by finding the new
minimum-weight outgoing edge (MOE) between them.

\begin{figure}[htbp]
\centering
\includegraphics[width=\linewidth]{imgs/failure.png}
\caption{A link of the tree fails (in red). The network is split in two fragments( the circles). The minimum between the outgoing edges (in green) has to be found to reconnect the fragments and maintain the MST.}
  
\label{fig:failure}
\end{figure}

The response proceeds in four phases. Phases 1, 2, and 4 are shared between both protocol
variants; Phase 3 admits two implementations with different complexity and correctness
guarantees.

\paragraph{Detection and split.}

Both endpoints of the failed link are notified of the failure.

Both endpoints generate a new unique fragment identity:

\begin{itemize}
    \item node $v$ generates the identity $(w(e), u, k(e))$;
    \item node $u$ generates the identity $(w(e), v, k(e))$;
\end{itemize}
where $w(e)$ is the weight of the failed link, $u$ and $v$ are the identifiers of the
endpoints, and $k(e)$ is a counter that is incremented each time the link fails and
is added. Without the counter, the same link could generate the same identity multiple
times.

Node $v$ (the child) immediately declares itself the root of its new fragment and enters
the \emph{reiden} state.

Node $u$ (the parent) propagates the information of the failure upward toward the root
$r$ of its fragment. Upon receiving this notification, $r$ enters the \emph{reiden} state.

\paragraph{RE-IDENtification.}

The root broadcasts the change down the tree so that every node in the fragment learns the
new identity.

Each receiving node updates its local identity, enters the \emph{reiden} state, and
forwards the message to its children.

Leaf nodes immediately acknowledge the change; internal nodes wait until acknowledgements
have been received from \emph{all} children before propagating the echo upward.

When the root collects acknowledgements from every child, every node in the fragment
shares the same identity and this phase is complete.

\paragraph{Minimum outgoing edge search.}

The goal of this phase is to identify the minimum-weight edge crossing the boundary
between the fragment $F$ and the rest of the network.
Two algorithms with different properties are provided.

\subparagraph{Naive.}

The root starts an echo wave down the tree to collect information about outgoing edges.

Each node receiving the echo wave:
\begin{itemize}
\item collects its outgoing edges by comparing its own identity with the identities
reported by its neighbors. To do so, it sends a \textsc{Test} message in each non-tree
link, together with its own identity. The neighbor replies positively if its identity is
different. The neighbors that replied positively are connected by outgoing edges, and
their weights are reported back to the sender.
\item decides its local MOE (the minimum-weight outgoing edge among its own outgoing edges
and those reported by its children).
\item sends the local MOE to its parent.
\end{itemize}

When the root has received all replies, it determines the global MOE of the fragment. If
no outgoing edge was found the protocol terminates, as the fragment is isolated from the
rest of the network. Otherwise, the root enters the \emph{merge} state and proceeds to the
next phase.

This implementation is simple and deterministic, but its message complexity is $O(e)$
since every node must test all its incident edges.

\subparagraph{Binary search.\cite{king2015constructionimprompturepairmst}}

For dense networks where $e = \Omega(n\log n)$, the $O(e)$ cost of the naive phase 3
dominates the overall failure-response complexity.

We propose an alternative approach to lower the complexity to $O(n\log n)$ in the average
case.
\smallskip

\noindent\textbf{TestOut: XOR-based outgoing edge existence detection.}

Property: an outgoing edge is incident to exactly one node in the fragment, while an
internal edge is incident to two nodes in the fragment.

The idea of the \textsc{TestOut} primitive is to exploit this property to determine
whether any outgoing edge exists in a given weight interval $[a,b]$ by computing the
XOR of the identifiers of all edges in that interval:
\begin{itemize}
\item Internal edges are counted twice (once by each endpoint) and therefore cancel out in
the XOR: $a \oplus a = 0$.
\item Outgoing edges are counted only once (by the endpoint in the fragment) and therefore
remain in the XOR. % TODO: argue about possible conflicts
\end{itemize}

In particular, each edge $e = (u,v)$ is assigned a symmetric unique identifier
$\mathrm{id}(e) = \bigl(\min(u,v),\,\max(u,v)\bigr)$. Each node computes the XOR of the identifiers of its incident edges whose weights fall in $[a,b]$:
$$
x_v = \bigoplus_{e \in \delta(v) \cap [a,b]} \mathrm{id}(e)
$$

The root collects the $x_v$ values from all nodes in the fragment and aggregates:
$$
X = \bigoplus_{v \in V(F)} x_v
$$

If $X = 0$, no outgoing edge exists in the interval; otherwise, at least one outgoing edge
exists.

This procedure is just a broadcast (of the interval) followed by an echo (of the local XOR
values), and therefore costs $O(n)$ messages.

\medskip

\noindent\textbf{The binary search.}

Now that we can test for the existence of outgoing edges in a given weight interval, we
can perform a binary search over the range of possible edge weights to find the
minimum-weight outgoing edge.

\begin{enumerate}
 
    \item \textbf{Initialize.}
        The root sets the search interval $[a,b] \gets [1, W]$, where $W$ is the
        maximum possible edge weight, known to all nodes as a system parameter.

    \item \textbf{Check existence.}
        Run \textsc{TestOut}$(F,\,1,\,W)$.
        If the result is zero, no outgoing edge exists, the root broadcasts
        \msg{GoSleep} and all nodes enter the \emph{sleep} state.
        Otherwise continue.
 
    \item \textbf{Estimate the median.}
        The root broadcasts the current interval $[a,b]$. Each node $v$ assigns a
        \emph{priority} to each of its incident non-tree edges $e$ whose weight falls in
        $[a,b]$:
        \[
            \mathrm{priority}(e)
            \;=\;
            H\!\left(s_{\mathrm{sk}} \;\|\; \mathrm{id}(e)\right),
        \]
        Each node retains only the $k$ edges with the \emph{smallest} priority values,
        discarding all others.

        During the convergecast, each internal node merges its own set of edges with those
        received from its children, deduplicates by edge identifier, and forwards the $k$
        globally smallest priorities to its parent.
        The root collects approximately $k$ uniformly random non-tree edges from across
        the fragment; the \textbf{median of their weights} is used as the split point~$m$.

        The parameter $k$ is a configurable constant that controls the quality of the
        median estimate: larger $k$ yields a more balanced split but increases per-round
        message size.

        % TODO: How good is the approximation?
 
    \item \textbf{Test both halves.}
          Run \textsc{TestOut} on $[a,m]$ and $[m{+}1,b]$. The root narrows the search to
          the \emph{lighter} sub-interval that contains at least one outgoing edge:
          \[
              [a,b] \;\gets\;
              \begin{cases}
                  [a,\,m]     & \text{if } \textsc{TestOut} [a,\,m] \neq 0 \\
                  [m{+}1,\,b] & \text{otherwise.}
              \end{cases}
          \]
 
    \item \textbf{Iterate.}
          For the new interval $[a,b]$, we iterate the algorithm by computing the new median and splitting the interval again. Because the interval strictly shrinks at each step, it eventually collapses to a single weight value $a = b = w^*$, which uniquely identifies the MOE weight.
 
    \item \textbf{Identify the edge.}
          When $a = b = w^*$, the root broadcasts $w^*$.
          Since edge weights are globally distinct (a standing assumption of the
          protocol), at most one node $p$ in $F$ holds an incident non-tree edge of
          weight~$w^*$.
          Node $p$ sends $\textsc{Test}\langle id \rangle$ over that edge; since the binary
          search confirmed an outgoing edge at weight $w^*$, the response is guaranteed
          to be \textsc{Accept}.
          Node $p$ thereby becomes the confirmed MOE holder and proceeds to Phase~4.
 
\end{enumerate}

\smallskip
\noindent\emph{Collisions:} The XOR test has no false positives: if $X \neq 0$ then at
least one outgoing edge exists in the interval. However, it may have false negatives if
two or more outgoing edges exist in the interval and their identifiers happen to cancel
out in the XOR.
For a non-empty set $S$ of outgoing edges with independent m-bit hash values,
\[
  \Pr\!\left[\bigoplus_{e \in S} h_{\mathrm{xor}}(e) = 0\right]
  \;=\; 2^{-m}
\]

This follows because the XOR of independent, uniformly distributed $m$-bit
values is itself uniformly distributed over the $2^m$ possible bit patterns.
Therefore the aggregate hash is equally likely to be any $m$-bit string, and
the probability of obtaining the all-zero value is exactly $1/2^m$.


\paragraph{Fragment merge.}

The root sends a message down the tree to inform the node $p$ at the MOE that it needs to
connect to the neighboring fragment.

Upon receiving this message, $p$ sends \msg{Connect}$\langle id \rangle$ over the MOE to
the endpoint in the neighboring fragment.

The two fragments then merge into a single extended fragment. If no further topological
changes have occurred in the meantime, the protocol proceeds identically to GHS: the
merged fragment elects a new root, generates a new identity, and begins a fresh MOE search
for the next phase of tree construction.

If a concurrent topological changes have occurred while this process was in progress, the
fragment identity mechanism handles them correctly: any messages carrying a superseded
identity are silently discarded, and the most recent failure or addition initiates a new
protocol round with a fresh identity. % da qualche parte dobbiamo dire che potrebbero esserci versioni diverse del MST in giro per la rete allo stesso tempo (se un nodo non ha ancora ricevuto il broadcast con il nuovo id)

\paragraph{Complexity.}
We already argued that the protocol to find the approximate median has $O(n)$ message complexity. The same argument can be applied to the \textsc{TestOut} primitive, which is also a broadcast followed by an echo. In the average case, the binary search over the edges requires $O(\log n)$ iterations to converge to a single weight value. Therefore, the overall message complexity of the binary search approach is $O(n \log n)$ in the average case. Each message carries a constant number of identifiers and weights, so the message size is $O(\log ID + \log W)$ bits where $ID$ is the maximum node identifier and $W$ is the maximum edge weight.

\subsubsection{Addition response protocol}
 
When a link $e = (u,v)$ is added to the network, two cases arise depending on whether
its endpoints belong to the same fragment or to different fragments.

To check whether $u$ and $v$ are in the same fragment, each endpoint sends a
\msg{IdCheck}$\langle id \rangle$ message to the other, where $id$ is the sender's current
fragment identity.
 
\paragraph{Same fragment.}
If $u$ and $v$ are in the same fragment (i.e., they have the same fragment identity), the
new link $e$ introduces a cycle with the existing tree edges.

To preserve the MST property, the maximum-weight edge in that cycle must be identified and
removed. The addition response proceeds in three phases.

\subparagraph{LCA.}
If $u$ and $v$ share the same fragment identity, each sends a
\msg{Addition}$\langle id,\, w(e)\, a,\, w \rangle$ message toward the root of the fragment,
where $w(e)$ is the weight of the new link, $a$ is the id of the node and $w$ is the 
running maximum weight along the path traversed so far.
Each intermediate node $z$ forwards the message to its parent, updating the running
maximum to $w' = \max\{w,\, w(\text{link to parent of } z)\}$.

The two messages propagate upward until they converge at the \emph{least
common ancestor} $\mathrm{lca}(u,v)$: the first node that receives two \msg{Addition}
messages for the same addition event, one arriving from the subtree containing $u$ and one
from the subtree containing $v$.

The first \msg{Addition} message to arrive at $\mathrm{lca}(u,v)$ will travel to the root,
while the second is blocked to avoid parents of $\mathrm{lca}(u,v)$ mistakenly receiving
two \msg{Addition} messages and incorrectly concluding that they are the LCA.

At this point $\mathrm{lca}(u,v)$ holds the weight of the heaviest edge in
the cycle.

\subparagraph{Update Topology.}

If the heaviest edge in the cycle is the same as the new link $e$, no further action is
needed: the MST remains unchanged and the protocol terminates.

If that is not the case, $\mathrm{lca}(u,v)$ sends a \msg{Replace}$\langle id,\, a, w \rangle$, 
where $w$ is the weight of the maximum-weight edge in the cycle and $a$ is the id received with
the message containing $w$, to the children that reported the maximum weight in the cycle:

\begin{itemize}
  \item If the node is not adjacent to the maximum-weight link, it simply forwards the message
        to the next node of the cycle.
  \item If a node that receives the message is adjacent to the link with
        the maximum weight, it removes that link from the MST and will forward 
        to the next node of the cycle the message:
        \msg{Replace}$\langle id,\, w(e), \infty \rangle$
  \item A node, that is not $u$ or $v$, that receives a \msg{Replace} message with $w = \infty$ 
        forwards it to the next node in the cycle and then reverses the parent-child relation
  \item When $u$ (resp. $v$) receives a \msg{Replace} message with $a = u$(resp. $a = v$) and 
        $w = \infty$, adds the new link $(u,v)$ (resp. $(v,u)$) to the MST.
\end{itemize}

      The new link $e$ is now part of the MST iff $w(e) < w_{\max}$, where $w_{\max}$ is
the weight of the maximum-weight edge in the cycle.

To avoid this, the root serializes additions using a token. The serialization order is
determined by the order in which the root receives \msg{Addition} messages from its
children. The first \msg{Addition} message to arrive is processed immediately, while any
subsequent \msg{Addition} messages are queued until the first addition is complete.

So, when there aren't other additions in progress, the root pops the first \msg{Addition}
message from its queue and it responds with \msg{Privilege}$\langle id,\, w \rangle$,
which travels down the same path and then around the cycle, releasing any blocked
\msg{Addition}$\langle id,\, w,\, _,\, _ \rangle$ messages it encounters. Note that only
addition messages with $w$ weight (i.e. for the event selected by the root) are released,
while other addition messages remain blocked until their turn comes.

A node holding a blocked \msg{Addition}$\langle id,\, w,\, _,\, _ \rangle$ forwards it upon
receiving \msg{Privilege}$\langle id,\, w \rangle$, allowing the LCA to eventually collect
both halves of the addition.

The root thus enforces a total order on concurrent additions, eliminating all deadlocks.

\paragraph{Different fragments.}
If $u$ and $v$ are in different fragments (i.e., they have different fragment identities),
there can be two different cases:
\begin{itemize}
  \item if $u$ (or $v$) is in sleep state, it means that the network was partitioned and
        the link $(u,v)$ connects the two partitioned fragments. In this case, node $u$ 
        (or $v$) sends a request to the root of its fragment to add the link $(u,v)$ to 
        the MST.
  \item Otherwise, a failure response protocol is already in progress. In this case the
        failure needs to be resolved first: node $u$ and $v$ will wait for \msg{REIDEN}
      message and check again if the they are in the same fragment, when they do the 
      addition response protocol will be started. If they are still in different fragments
        eventually they will go in sleep state and the first case will be applied.
\end{itemize}

\paragraph{Complexity.}
A single addition costs $O(n)$ messages: the \msg{Addition} messages travel only in one direction along
tree links, and the \msg{Replace} phase traverses the cycle, which is also a subset of
tree links. The message size is $O(\log ID + \log W)$ bits, where $ID$ is the maximum node identifier and $W$ is the maximum edge weight.

\section{Development plan}
% Since it is difficult to predict just how hard implementing a new system will be, you should formulate as a set of ``tiers,'' where the basic tier is something you’re sure you can complete, and the additional tiers add more features, at both the application and the system leve

The implementation will be organized in cumulative tiers, starting from a minimal
baseline and progressively adding the dynamic behavior described in the previous
sections. 

\paragraph{Tier 1: GHS baseline.}
The first milestone is a static distributed MST implementation based on the
Gallager Humblet Spira algorithm. This version establishes the basic distributed
infrastructure, including message passing, fragment management, and root election, but
assumes that the network topology remains stable after the initial construction.

\paragraph{Tier 2: Dynamic repair with the naive deletion phase.}
The second milestone extends the baseline with our dynamic repair algorithm for
link failures, using the $O(|E|)$ naive Phase~3 described in this chapter. At this stage
the system handles one topological event at a time and does not yet support concurrent
failures or additions. This tier is intended to validate the correctness of the failure
response protocol and the fragment reidentification mechanism.

\paragraph{Tier 3: Full dynamic algorithm.}
The third milestone adds the complete behavior of the system: the binary-search-based
minimum outgoing edge search, addition handling, and the mechanisms needed to cope with
concurrent failures and additions. At the end of this stage, the implementation should
match the full protocol described in the project chapter.

\paragraph{Tier 4: Additional improvements.}
If time permits, the final tier will explore optional enhancements that are not required
for the core project. Possible extensions include alternative methods for estimating the
median during Phase~3, such as a distributed selection algorithm, and further
optimizations.
